# dsh-wiki-tools v1：右侧栏知识图谱并点开文件

## 问题

使用者在 DSH Web 里已经能用第三方浏览插件打开 `wiki/`、点 `[[wikilink]]`、看背链和体检，但仍必须打开 Obsidian 才能看到页面之间的关系图。知识库是一份 Obsidian 式双链 Markdown（约 20 页、约 140 条链接），图谱本身不需要编辑或重建目录。

## 方案

做一个树外 Web 插件 `dsh-wiki-tools`（工具箱包，v1 只交付第一件能力）。在右侧栏「开始」放一张「知识图谱」引导卡，打开一个页签，画出当前会话工作区 wiki 根下页面与 `[[wikilink]]` 的力导向图。点节点即打开对应 Markdown：装着浏览插件时由它渲染，没装则落到产品自带预览。本插件只读、不写盘，不依赖那个浏览插件。

## 实现决策

- 新建树外插件包 `dsh-wiki-tools`（npm 名不加他人 scope），工程形态与仓里已有的树外 Web 插件同构；Cordis 行 id 为 `wiki-tools`；只声明 Web 客户端平台。
- v1 只注册一个右侧栏页面类型：`kind` 为 `wiki-graph`，不声明地址匹配，靠打开页签进入。引导卡写在该类型的 `guide` 上。不挂会话顶栏按钮，不做工具箱首页。
- 工程：TypeScript、打包、客户端 React、单测；profile 用 `link:` 挂 bundle。通信不上 Remote CRUD：图谱是一次性只读，宿主注册 `GET /wiki-graph/graph`（查询参数带会话工作区和可选根），不引入 Typert 代码生成。
- 配置：`root` 默认 `wiki`，相对会话工作区，必须落在工作区内，拒绝 `..` 越界。v1 不做多 wiki 切换器。
- 只读：`readFile` / `readdir`，绝不写盘。扫描跳过 `.obsidian/`、`node_modules/`、`.git/`。
- 解析：收根下全部 `**/*.md`。frontmatter 只取 `title` / `type` / `tags` / `status`（`---` 分段 + 逐行 `key: value`，不引 YAML 库）。链接匹配 `[[target]]` / `[[target|别名]]` / `[[target#锚点]]`，去掉别名和锚点后按文件名（去扩展名）解析；`[[x]]` 认 `x.md` 与 `x`。重名则边连到每一个匹配，统计记 `ambiguousCount`。围栏代码块内的 `[[...]]` 不计。
- 点节点：`openResource(会话文件地址)`，不指定 `kind`，`preferNewPane: true`。由页签注册表排序决定渲染方。
- 渲染：SVG 手写力导向（斥力 + 弹簧 + 向心），固定迭代次数后停，固定随机种子。节点半径随度数；颜色按 `type`。孤儿加灰色虚线圈。断链目标不进图。搜索与 type 过滤降透明度、不重排。样式只用产品语义 token。
- 刷新策略：打开页签时取数；不做文件监听。
- 与浏览插件零 import、零共享运行时。它升级或卸载不影响本包加载。

图谱文档（宿主返回、客户端只消费这一份）：

```ts
// 决策形状，不是实现草稿
type WikiGraph = {
  nodes: Array<{
    id: string
    title: string
    type: string
    tags: string[]
    path: string
    degree: number
    orphan: boolean
  }>
  edges: Array<{ source: string; target: string }>
  missing: string[]
  stats: {
    pageCount: number
    edgeCount: number
    orphanCount: number
    brokenCount: number
    ambiguousCount: number
  }
}
```

`edges` 只连接已存在的节点；解析失败的目标进 `missing` 并计入 `brokenCount`，不进 `nodes`。

## 测试决策

**接缝（一条）**：wiki 目录 → 图谱文档。宿主扫描函数（GET 处理器也只调它）是唯一对外契约。不测力导向迭代、不测 SVG 坐标、不测 CSS。

覆盖这组对外行为，用临时目录夹具，不访问真实知识库：

- 20 页量级的典型库：节点数 = `.md` 数，边数与正文 `[[wikilink]]` 一致（去掉代码块、别名、锚点后）。
- 代码块里的 `[[示例]]` 不成边。
- 断链进 `missing` / `brokenCount`，不进 `nodes`。
- 两个同名 `foo.md`：每条 `[[foo]]` 对每个匹配都有边，`ambiguousCount > 0`。
- `root` 含 `..` 或逃出工作区：拒绝，不读盘外文件。
- Windows 盘符路径是绝对路径，不是 URL scheme。
- 无工作区 / 根不存在 / 无页面：稳定的空或错误结果，不抛未分类异常。

客户端只测接缝的消费面：页面类型带引导卡；点节点调用 `openResource` 且不指定 `kind`、带 `preferNewPane`。用测试运行时夹具，不启动浏览器。

参照仓里已有树外插件的宿主夹具（临时工作区 + 会话）和客户端插槽注册测试；不要抄 Remote CRUD 测试。

## 不在范围内

- 浏览目录、原地渲染 `[[wikilink]]`、背链、12 项体检（已有浏览插件）。
- 写入、编辑、ingest、检索问答、助手对话。
- 工具箱外壳、会话顶栏按钮、多 wiki 切换器。
- 局部图谱、标签当节点、附件当节点、WebGL、持续动画、保存节点坐标、文件监听。
- Desktop GUI、Typert Remote、改第三方浏览插件、改 DSH 本体包。

## 其他

- 使用者当前知识库工作区默认根为 `wiki/`。浏览插件已装在 web profile，用于验收「点节点进它的页签」；卸掉它再验「落到原生预览」。
- 浏览插件只扫四类目录，列表里主要是 concept；本图按磁盘全量 `.md`，会多出 `sources/`、`courses/` 和根级 `overview` / `glossary` / `index` / `log`。这是有意的。
- `index.md` 导航链多，会成为超级节点；用 type 上色和过滤压视觉，不从节点集里删掉。
- 包是工具箱，v1 只交付图谱。以后第二件能力在同一 Cordis 行上再注册页签，不改这次的 `kind`。
- npm 包名是 `dsh-wiki-tools`，不要套用其他开发者的 scope。
